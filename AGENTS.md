## Перед началом

- Загрузите навык `samber/cc-skills-golang@golang-how-to` перед любой работой с Go-кодом, ревью, отладкой, устранением неполадок или настройкой — он направит к нужным Go-навыкам.
- Проверьте доступные навыки и в зависимости от задачи добавьте необходимые.
- Прочитайте [architecture.md](architecture.md) перед изменениями пайплайнов, шифрования, идентичности S3, кэша или HTTP. Это источник истины для границ компонентов и форматов — реализуйте по нему, а не по новому дизайну, если пользователь явно не пересмотрит. Не придумывайте вторую схему идентичности или второй формат шифротекста.

## Что это за репозиторий

Go CLI (`github.com/xMlex/s3vault`, `go 1.26`), который архивирует файлы старше заданного периода в S3-совместимое хранилище или локальную директорию, при необходимости шифрует на клиенте, скачивает/расшифровывает и может отдавать открытый текст через S3 API facade (SigV4; постоянный дисковый кэш опционален, по умолчанию выключен).

| | |
| --- | --- |
| Точка входа | `cmd/s3vault` (`main`: сигналы, коды выхода, version ldflags) |
| Логика | только `internal/`; нет публичного `pkg/` |
| Документация для операторов | [README.md](README.md) — сборка, развёртывание, режимы шифрования |
| Примеры конфигурации | `s3vault.example.yaml`, `.env.example` |
| Инструментарий | `Makefile` (`make build`, `make test`, `make lint`, `make fmt`) |
