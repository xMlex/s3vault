# Архитектура

## Общие требования

- Использовать модульную архитектуру с чёткими границами ответственности.
- Разделять бизнес-логику и инфраструктурные детали.
- Минимизировать связанность между модулями.
- Стремиться к высокой связности внутри модулей.
- Предпочитать композицию наследованию.
- Использовать dependency injection там, где это упрощает тестирование и управление зависимостями.
- Избегать циклических зависимостей.
- Не допускать утечки деталей реализации между слоями.
- Публичные интерфейсы должны быть минимальными и стабильными.

## Архитектурные принципы

Использовать SOLID, DRY, KISS и YAGNI как инструменты принятия решений, а не как самоцель.

Допускается использование:

- Clean Architecture;
- Hexagonal Architecture;
- Domain-Driven Design;
- Repository Pattern;
- CQRS;

только если сложность и требования проекта действительно оправдывают их применение.

Не внедрять микросервисную архитектуру, event-driven архитектуру или дополнительные слои без обоснованной необходимости.

## Границы ответственности

Каждый модуль должен иметь:

- Чёткую ответственность.
- Понятный публичный интерфейс.
- Минимальное количество внешних зависимостей.
- Возможность независимого тестирования, где это оправдано.
