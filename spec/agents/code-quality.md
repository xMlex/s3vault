# Качество кода

- Код должен быть понятен разработчику, который впервые знакомится с проектом.
- Имена переменных, функций, типов и модулей должны отражать их назначение.
- Функции должны выполнять одну логически связанную задачу.
- Избегать чрезмерно длинных функций и больших классов.
- Не использовать магические числа и строки без необходимости.
- Предпочитать явное поведение неявному.
- Не создавать универсальные решения для узкоспециализированных задач.
- Не усложнять код ради потенциального повторного использования.
- Не дублировать комментариями то, что очевидно из кода.
- Документировать публичные API и неочевидные архитектурные решения.

При рефакторинге:

- Сохранять существующее поведение.
- Не смешивать рефакторинг с изменением бизнес-логики без необходимости.
- Не удалять существующие проверки и обработку ошибок без обоснования.
- Сохранять обратную совместимость, если иное не согласовано.
