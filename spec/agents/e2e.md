# E2E-обвязка

`compose.e2e.yaml` + `scripts/e2e.sh`. Механика прокомментирована в скрипте; вот ловушки:

- `encryption.mode=command` проверяется подменой `cryptcp` на `scripts/e2e/fakecryptcp`, который зеркалит реальный контракт (argv, `CRYPTOPRO_THUMBPRINT` из env, ключ из SHA-1 thumbprint), но **не криптография и не ГОСТ**. Тестирует пайплайн, а не CryptoPro.
- Фаза `go` запускает unit-тесты **без `S3VAULT_*` в окружении** — только бинарь и `-tags=integration` получают его (массив `S3_ENV`). `S3VAULT_S3_PREFIX` перебил бы тесты префиксов локального бэкенда.
- Префикс уникален на запуск (`S3VAULT_E2E_RUN_ID`), иначе повторный запуск увидит предыдущие объекты и получит skip вместо upload.
- Сбой S3 моделируется прокси `socat`, а не `docker compose stop`, поэтому фазе не нужны права Docker.
- Контракты, которые harness закрепляет, а не чинит: ключ объекта относительно корня скана; `S3VLT01` на смещении 128 внутри `S3VCTR01`; идентичность из CRC-заголовка, без чтения тела на `Head` (поэтому повреждённый AEAD-тег ловится только `download`); `s3.prefix` удалённого клиента становится частью ключа и складывается с серверным.
